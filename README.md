# E2EEチャットアプリ
ユーザー間で直接安全な暗号鍵を交換し、サーバー側でメッセージの内容を解読できないように設計された、セキュリティ特化型のリアルタイム1対1チャットアプリケーションとなっている。

---

## 📌 本プログラムの5W1H

* **Who（誰が使うのか）**
  * セキュリティやプライバシーを最優先にしたい人、第三者に会話を絶対に覗かれたくないふたりのユーザー。
* **What（何を提供するのか）**
  * 「E2EE（エンドツーエンド暗号化）」を徹底した、安全な1対1のリアルタイムチャット空間。
* **When（どんな時に使うのか）**
  * 5分間で自動更新される「動的ワンタイムID」でお互いを検索し、鍵交換の申請・承認が成立したとき。
* **Where（どこで機能するのか）**
  * 暗号化と復号はすべて「ユーザーのブラウザ上（フロントエンド）」で完結。サーバーや通信線上には解読不可能な暗号文のみが存在します。
* **Why（なぜ作ったのか）**
  * 運営会社やサーバー管理者にデータを覗き見られるリスクを排除し、ユーザーの通信の秘密を完全に守るため。
* **How**
  * Web Crypto API（AES-GCM）によるクライアントサイド暗号化、Socket.ioによるリアルタイムな画面ロック制御、そして「関心の分離」を意識したクリーンなファイル分割。

---

## 特徴

### 1.E2EE
* **ブラウザ側での暗号化・復号:** メッセージは送信前にWeb Crypto API（AES-GCM）を用いてブラウザ上で暗号化され、サーバーには暗号文（十六進数の文字列）のまま送信・保存される。
* **サーバーは中継のみ:** データベース（PostgreSQL）には暗号化されたメッセージしか残らないため、サーバー管理者や悪意のある第三者がデータベースを覗き見ても、チャット内容を解読することは難しい。

### 2.安全な1対1鍵交換システム（Key Exchange）
* **ワンタイムIDによる匿名検索:** ユーザー間の接続（鍵交換）は、自動更新される「6桁の動的ワンタイムID」を用いて行う。これにより、常時公開される固定のメールアドレス等からアカウントを特定されるリスクを抑えている。
* **申請と承認・拒否のワークフロー:** 鍵交換の申請時、申請者は自身のログイン情報（ハッシュ値）を使って共通鍵を暗号化して送信する。受信側は「カギを受け取る」または「許可しない（拒否）」を選択でき、承認された場合のみお互いのブラウザで安全に復号が可能。

## 技術スタック

* **フロントエンド:** HTML5, CSS3, JavaScript, Web Crypto API (AES-GCM, SHA-256)
* **バックエンド:** Node.js, Express
* **リアルタイム通信:** Socket.io (WebSocket)
* **データベース:** PostgreSQL
